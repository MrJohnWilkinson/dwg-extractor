# Bug: Polygon Count Discrepancy Due to Precision Snap Order

## Bug Description
The `_extract_paint_bucket_regions()` function in `app/core/geometry.py` reports incorrect polygon counts (5 instead of 7) for blocks with LINE entities that have floating-point precision errors in their endpoint coordinates. The symptom is that horizontal LINE dividers at Y=-535 and Y=535 fail to split vertical edges properly, causing shelf regions to be merged instead of separated.

**Actual behavior:** Block "SPAR Gulv 900x600 H1860" reports 5 polygons with incorrect areas.
**Expected behavior:** Block should report 7 polygons matching the visual layer structure.

## Problem Statement
The coordinate snapping (Stage 1 precision fix) is applied AFTER `unary_union()` instead of BEFORE. When `unary_union()` runs, LINE endpoints with nanometer-scale precision errors (e.g., `914.9999999962746` instead of `915.0`) do not exactly touch vertical edges, preventing proper edge splitting at intersection points. The subsequent `snap()` call only adjusts coordinate values but does NOT re-compute segment intersections.

## Solution Statement
Snap edge coordinates to a precision grid BEFORE calling `unary_union()`. This ensures that endpoints with floating-point artifacts are aligned to grid points before intersection detection occurs. The `unary_union()` operation will then correctly identify and split edges at intersection points.

Implementation:
1. Add a helper function `_snap_linestring_coords()` to snap LineString coordinates to a precision grid
2. Modify `_extract_paint_bucket_regions()` to apply coordinate snapping to edges BEFORE `unary_union()`
3. Remove the redundant post-union `snap()` call for Stage 1 (precision snapping)

## Steps to Reproduce
1. Create a block with:
   - A closed LWPOLYLINE forming a large rectangle (e.g., 900x1200)
   - Horizontal LINE dividers that should split the rectangle into multiple rows
   - LINE endpoints with floating-point precision errors (e.g., `(914.9999999962746, -535.0000000002328)`)
2. Call `_extract_paint_bucket_regions()` on the block
3. Observe that polygons are merged instead of split at the divider lines

## Root Cause Analysis
The current code flow in `_extract_paint_bucket_regions()`:

```python
# Step 1: Extract edges
edges = _extract_all_edges(block_def)

# Step 2: Merge and split at intersections
merged = unary_union(edges)  # BUG: Precision error prevents proper splitting

# Step 3: Snap coordinates (TOO LATE!)
merged = snap(merged, merged, precision_tolerance)  # Only moves points, doesn't re-split
```

When the LINE at Y=-535 has endpoint `(914.9999999962746, -535.0)` instead of `(915.0, -535.0)`:
- The left vertical edge IS split at Y=-535 (exact match at X=15)
- The right vertical edge is NOT split (no match at X≈914.999...)
- Result: Only 5 polygons instead of 7

The fix: Snap coordinates BEFORE `unary_union()`:

```python
# Step 1: Extract edges
edges = _extract_all_edges(block_def)

# Step 2: Snap coordinates FIRST (Stage 1)
if precision_tolerance > 0:
    edges = [_snap_linestring_coords(e, precision_tolerance) for e in edges]

# Step 3: THEN merge and split (intersections detected correctly)
merged = unary_union(edges)
```

### Step 1: Add Helper Function `_snap_linestring_coords()`
Add a new helper function to `app/core/geometry.py` that snaps LineString coordinates to a precision grid:

- Add the function near the other helper functions (around line 400)
- Function signature: `def _snap_linestring_coords(line: LineString, tolerance: float) -> LineString`
- Implementation rounds each coordinate to the nearest multiple of `tolerance`
- Return a new LineString with snapped coordinates

```python
def _snap_linestring_coords(line: LineString, tolerance: float) -> LineString:
    """Snap LineString coordinates to grid based on tolerance.

    Rounds each coordinate to the nearest multiple of tolerance to fix
    floating-point precision artifacts before geometric operations.

    Args:
        line: Shapely LineString to snap
        tolerance: Grid spacing for coordinate rounding

    Returns:
        New LineString with coordinates snapped to grid.
    """
    if tolerance <= 0:
        return line
    coords = [
        (round(x / tolerance) * tolerance, round(y / tolerance) * tolerance)
        for x, y in line.coords
    ]
    return LineString(coords)
```

### Step 2: Modify `_extract_paint_bucket_regions()` to Snap Before Union
Update `_extract_paint_bucket_regions()` in `app/core/geometry.py`:
