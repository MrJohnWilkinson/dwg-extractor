# Feature: ELLIPSE and SPLINE Entity Support in Geometry Functions

## Feature Description

Implement support for ELLIPSE and SPLINE entities in the three core geometry functions: `_get_block_bounding_box()`, `_extract_all_edges()`, and `_estimate_edge_count()`. Currently, these entity types are completely ignored, causing blocks containing ellipses or splines to have incorrect bounding boxes and potentially fail polygon detection for content zone analysis.

Both ELLIPSE and SPLINE entities support the ezdxf `flattening(distance)` method, which converts curved geometry to line segments. This follows the same pattern already used for ARC, CIRCLE, and HATCH entities in the existing codebase.

## User Story

As a CAD engineer using the DXF Block Extractor
I want ELLIPSE and SPLINE entities to be included in block geometry calculations
So that blocks containing these entity types have accurate bounding boxes and correct polygon detection for content zone analysis

## Problem Statement

ELLIPSE and SPLINE entities are completely ignored in all geometry functions in `app/core/geometry.py`:

1. **`_get_block_bounding_box()`** (lines 332-486): Entity type list does not include ELLIPSE or SPLINE. These entities do not contribute to bounding box calculation.

2. **`_extract_all_edges()`** (lines 878-952): Entity type checks do not include ELLIPSE or SPLINE. These entities are not extracted as edges for polygon detection via paint-bucket algorithm.

3. **`_estimate_edge_count()`** (lines 719-766): Entity type checks do not include ELLIPSE or SPLINE. Edge count estimation for these entities is missing, potentially causing inaccurate threshold comparisons.

**Impact:**
- Blocks containing ELLIPSE entities report bounding boxes that exclude the ellipse geometry
- Blocks containing SPLINE entities report bounding boxes that exclude the spline geometry
- Paint-bucket polygon detection fails to find regions bounded by ellipses or splines
- Edge count estimation is too low for blocks with ellipses or splines

## Solution Statement

Add ELLIPSE and SPLINE entity handling to all three functions using the `flattening()` method:

1. **ELLIPSE handling**: Use `entity.flattening(sagitta)` to convert the ellipse to line segments. Extract vertices for bounding box calculation and edge extraction.

2. **SPLINE handling**: Use `entity.flattening(sagitta)` to convert the spline to line segments. Include a fallback to control points for degenerate splines that fail flattening.

3. **Edge count estimation**: For ELLIPSE, use the Ramanujan approximation for ellipse perimeter to estimate segment count. For SPLINE, use control point count as a multiplier estimate.

The implementation follows existing patterns in the codebase:
- ARC handling in `_get_block_bounding_box()` uses `_get_arc_bounding_box()` for accurate bounds
- CIRCLE/ARC handling in `_extract_all_edges()` uses `_extract_circle_edges()` and `_extract_arc_edges()` helpers
- HATCH handling uses `from_hatch()` with `path.flattening(sagitta)`

### Step 5: Add `_extract_ellipse_edges()` Helper Function

Add new helper function in `app/core/geometry.py` after `_extract_arc_edges()` (around line 822):

```python
def _extract_ellipse_edges(entity: Any) -> list[LineString]:
    """Extract edges from ELLIPSE entity using adaptive flattening.

    Uses ezdxf's built-in flattening method with sagitta-based precision.
    The sagitta controls the maximum distance from curve to chord, producing
    more segments for larger ellipses and fewer for smaller ones.

    Args:
        entity: ezdxf ELLIPSE entity

    Returns:
        List of LineString objects representing the ellipse as line segments.
        Returns empty list if flattening fails.
    """
    try:
        points = list(entity.flattening(sagitta=ARC_FLATTENING_SAGITTA))
        edges: list[LineString] = []
        for i in range(len(points) - 1):
            edges.append(
                LineString(
                    [(points[i].x, points[i].y), (points[i + 1].x, points[i + 1].y)]
                )
            )
        return edges
    except (AttributeError, TypeError, ValueError):
        return []
```

```python
def _extract_spline_edges(entity: Any) -> list[LineString]:
    """Extract edges from SPLINE entity using adaptive flattening.

    Uses ezdxf's built-in flattening method with sagitta-based precision.
    Falls back to control points as edges for degenerate splines.

    Args:
        entity: ezdxf SPLINE entity

    Returns:
        List of LineString objects representing the spline as line segments.
        Returns empty list if both flattening and control point fallback fail.
    """
    try:
        points = list(entity.flattening(sagitta=ARC_FLATTENING_SAGITTA))
        edges: list[LineString] = []
        for i in range(len(points) - 1):
            edges.append(
                LineString(
                    [(points[i].x, points[i].y), (points[i + 1].x, points[i + 1].y)]
                )
            )
        return edges
    except (AttributeError, TypeError, ValueError):
        # Fallback to control points as edges for degenerate splines
        try:
            cps = list(entity.control_points)
            edges: list[LineString] = []
            for i in range(len(cps) - 1):
                edges.append(
                    LineString([(cps[i].x, cps[i].y), (cps[i + 1].x, cps[i + 1].y)])
                )
            return edges
        except (AttributeError, TypeError):
            return []
```

### Step 8: Add ELLIPSE Estimation to `_estimate_edge_count()`

Add ELLIPSE estimation in `app/core/geometry.py` `_estimate_edge_count()` function after ARC estimation (around line 759):

```python
elif entity_type == "ELLIPSE":
    # Estimate based on ellipse perimeter using Ramanujan approximation
    try:
        # Get semi-major and semi-minor axes
        major_axis = entity.dxf.major_axis
        a = major_axis.magnitude  # Semi-major axis length
        ratio = entity.dxf.ratio  # Ratio of minor to major axis
        b = a * ratio  # Semi-minor axis length

        # Ramanujan approximation for ellipse perimeter
        h = ((a - b) ** 2) / ((a + b) ** 2) if (a + b) > 0 else 0
        perimeter = math.pi * (a + b) * (1 + (3 * h) / (10 + math.sqrt(4 - 3 * h)))

        # Estimate segments based on sagitta (use max radius for conservative estimate)
        max_radius = max(a, b)
        if max_radius > 0 and ARC_FLATTENING_SAGITTA > 0:
            estimated = int(perimeter / (2 * math.sqrt(2 * max_radius * ARC_FLATTENING_SAGITTA)))
            count += max(8, estimated)
        else:
            count += 36  # Default fallback
    except (AttributeError, TypeError, ValueError):
        count += 36  # Default estimate if properties unavailable
```

## Notes

1. **ezdxf `flattening()` method**: Both ELLIPSE and SPLINE entities support `flattening(distance)` which returns an iterator of Vec3 vertices. The `distance` parameter is the sagitta (maximum distance from arc to chord).

2. **ELLIPSE properties**:
   - `entity.dxf.major_axis`: Vec3 defining the major axis direction and length
   - `entity.dxf.ratio`: Ratio of minor to major axis (0 < ratio <= 1)
   - `entity.dxf.start_param` / `entity.dxf.end_param`: Parametric start/end for elliptical arcs

3. **SPLINE properties**:
   - `entity.control_points`: Sequence of Vec3 control points
   - `entity.dxf.degree`: Spline degree (typically 3 for cubic)
   - `entity.closed`: Boolean indicating closed spline

4. **Ramanujan approximation for ellipse perimeter**:
   ```
   h = ((a - b)^2) / ((a + b)^2)
   P = pi * (a + b) * (1 + (3h) / (10 + sqrt(4 - 3h)))
   ```
   This provides ~0.01% accuracy for most ellipse shapes.

5. **Pattern consistency**: This implementation follows the same patterns used for:
   - ARC bounding box: Uses helper function for accurate calculation
   - CIRCLE/ARC edge extraction: Uses dedicated helper functions
   - HATCH edge extraction: Uses `flattening()` with sagitta parameter

6. **Performance consideration**: `flattening()` is O(n) where n is the number of output segments. The sagitta parameter `ARC_FLATTENING_SAGITTA = 0.1` provides good balance between accuracy and performance.

7. **Reference document**: Detailed analysis in `ai_output/087-geometry-handling-gap-analysis-report.md` Sections 2.1 (ELLIPSE) and 2.2 (SPLINE).

8. **Prior unit learnings**:
   - **Unit 1 (LWPOLYLINE Bulge)**: Used `make_path()` for path handling. Pattern: Create test asset generator script, generate DXF, add tests.
   - **Unit 2 (Nested INSERT)**: Added `_transform_bbox_points()` helper. Updated function signatures with optional parameters. 14 new tests added.
   - **ARC bbox**: Using `flattening(sagitta)` method works well for curved entities.

9. **Import statement**: The `math` module is already imported in `geometry.py` (line 22). The `ARC_FLATTENING_SAGITTA` constant is already imported from `constants.py` (line 36).
