# Feature: Net Area Content Zone Detection

## Feature Description
Automatically identify the "content zone" shape within a CAD block definition by analyzing closed polygon geometry. The content zone is defined as the shape with the largest net area (own area minus sum of fully-contained shape areas). This enables automatic derivation of trim values (distance from block bounding box to content zone bounding box), reducing manual data entry for block geometry analysis.

The system detects closed polygons using two complementary methods:
1. **LWPOLYLINE detection**: Identify closed polylines of any vertex count
2. **LINE cycle detection**: Find closed cycles from connected line segments using graph-based analysis

Both methods run simultaneously and results are merged before net area calculation, ensuring correct detection regardless of how the CAD author drew the shapes.

## User Story
As a DXF block analyzer
I want to automatically identify the "content zone" shape in a block
So that I can derive trim values (distance from block bounding box to content zone bounding box) and reduce manual data entry

## Problem Statement
Currently, users manually inspect each block and enter trim values (Trim Left, Trim Right, Trim Top, Trim Bottom) into Excel columns. This process is time-consuming and error-prone for large block libraries. The system already extracts block geometry (bounding box, segments) but doesn't identify the meaningful "content zone" within blocks that have nested shapes (outer borders, inner content areas).

## Solution Statement
Implement automated content zone detection by:
1. Detecting all closed polygons in a block (both LWPOLYLINE and LINE-based)
2. Calculating area for each shape using the shoelace formula
3. Determining containment relationships between shapes using point-in-polygon tests
4. Computing net area for each shape (own area minus contained shapes' areas)
5. Selecting the shape with the largest net area as the content zone
6. Deriving suggested trim values from the content zone's bounding box relative to the block's bounding box
7. Adding new columns to the Block Geometry Analysis sheet with the results

### Step 1: Add Content Zone Data Types
- Add `ContentZoneData` TypedDict to `app/core/types.py`:

      suggested_trim_top: float | None
      suggested_trim_bottom: float | None

- Add type alias `Polygon = list[tuple[float, float]]` for vertex lists

### Step 2: Add Excel Column Constants

  - `EXCEL_COLUMN_BLOCK_SUGGESTED_TRIM_TOP: str = "block_suggested_trim_top"`

  - `EXCEL_COLUMN_BLOCK_CONTENT_ZONE_DETECTED: str = "block_content_zone_detected"`

### Step 3: Implement Shoelace Area Calculation
- Add function `_calculate_polygon_area(vertices: Polygon) -> float` to `app/core/geometry.py`
- Implementation: Shoelace formula: `0.5 * abs(sum(x[i]*y[i+1] - x[i+1]*y[i]))`
- Returns absolute value (always positive area)
- Handle edge cases: fewer than 3 vertices returns 0.0

### Step 4: Implement Point-in-Polygon Test
- Add function `_point_in_polygon(point: tuple[float, float], polygon: Polygon) -> bool` to `app/core/geometry.py`
- Use ray casting algorithm for accurate results with any simple polygon
- Handle edge cases: points on edges (treat as inside for containment purposes)

### Step 5: Implement Polygon Containment Check
- Add function `_polygon_contains_polygon(outer: Polygon, inner: Polygon) -> bool` to `app/core/geometry.py`
- Returns True if ALL vertices of inner polygon are inside outer polygon
- Uses `_point_in_polygon()` for each vertex check

### Step 6: Implement Polygon Bounding Box Extraction
- Add function `_get_polygon_bounding_box(polygon: Polygon) -> tuple[float, float, float, float]` to `app/core/geometry.py`
- Returns (min_x, min_y, max_x, max_y)
- Handle edge case: empty polygon returns (0.0, 0.0, 0.0, 0.0)

### Step 7: Implement LWPOLYLINE Closed Polygon Extraction
- Add function `_extract_closed_lwpolylines(block_def: BlockLayout) -> list[Polygon]` to `app/core/geometry.py`
- Iterate through block entities, filter for LWPOLYLINE/POLYLINE with `is_closed` flag
- Extract vertex coordinates into Polygon format
- Skip polylines with fewer than 3 vertices

### Step 8: Implement LINE Cycle Detection
- Add function `_extract_line_cycles(block_def: BlockLayout) -> list[Polygon]` to `app/core/geometry.py`
- Build adjacency graph from LINE entities (endpoints as nodes)
- Use tolerance (epsilon=0.01) for connecting endpoints
- Detect cycles using DFS/BFS-based cycle detection
- Convert detected cycles to Polygon vertex lists
- Filter out cycles with fewer than 3 unique vertices

### Step 9: Implement Net Area Calculation
- Add function `_calculate_net_areas(polygons: list[Polygon]) -> list[tuple[Polygon, float]]` to `app/core/geometry.py`
- For each polygon, calculate net_area = own_area - sum(contained polygon areas)
- Use `_polygon_contains_polygon()` to determine containment
- Return list of (polygon, net_area) tuples

### Step 10: Implement Content Zone Detection
- Add function `_detect_content_zone(block_def: BlockLayout) -> ContentZoneData` to `app/core/geometry.py`
- Combine results from `_extract_closed_lwpolylines()` and `_extract_line_cycles()`
- Calculate net areas using `_calculate_net_areas()`
- Select polygon with maximum net area as content zone
- Calculate trim values from content zone bounding box vs block bounding box:
  - `suggested_trim_left = content_zone.min_x - block.min_x`
  - `suggested_trim_right = block.max_x - content_zone.max_x`
  - `suggested_trim_top = block.max_y - content_zone.max_y`
  - `suggested_trim_bottom = content_zone.min_y - block.min_y`
- Return `ContentZoneData` with results or None values if no shapes found

### Edge Cases
- No closed shapes in block -> all trim values None, content_zone_detected=False
- Single shape (no nesting) -> that shape is content zone, net_area = own_area
- All shapes equal area -> pick first detected (deterministic by detection order)
- Self-intersecting polygons -> excluded from consideration (shoelace gives incorrect area)
- Very small shapes (near-zero area) -> handled correctly
- Degenerate polygons (collinear points) -> area = 0, excluded
- Shapes touching but not containing each other

## Notes
- **Algorithm Complexity**: LWPOLYLINE detection is O(n) where n = number of entities. LINE cycle detection is O(n^2) naive implementation. Containment check is O(s^2) where s = number of shapes. Overall dominated by LINE cycle detection for blocks with many LINE entities.
- **Tolerance**: Use epsilon=0.01 for endpoint matching in LINE cycle detection, consistent with existing intersection point deduplication.
- **Deterministic ordering**: When shapes have equal net area, pick first detected. Detection order: LWPOLYLINEs first (iteration order), then LINE cycles (by cycle detection order).
- **Self-intersecting polygons**: Out of scope - shoelace formula gives incorrect area. Could add validation later if needed.
- **Curved shapes**: Out of scope - only straight-edge polygons (LINE, LWPOLYLINE). ARCs and SPLINEs are not considered.
- **Future enhancement**: Could add confidence score based on how much larger the max net area is vs. second-largest.
