# Feature: Nested INSERT Geometry Expansion for Bounding Box Calculation

## Feature Description

Implement recursive expansion of nested INSERT entities in `_get_block_bounding_box()` to include the geometry of referenced blocks when calculating bounding boxes. Currently, when block A contains an INSERT reference to block B, only block A's direct entities are included in the bounding box calculation. Block B's geometry is completely ignored, causing undersized bounding boxes and incorrect content zone detection.

This enhancement adds:
1. A `_transform_bbox_points()` helper function to transform nested block bounding box corners by INSERT properties (scale, rotation, translation)
2. Recursive INSERT entity processing in `_get_block_bounding_box()` with circular reference protection
3. Updated function signature to accept optional `doc` and `processed_blocks` parameters

## User Story

As a CAD engineer using the DXF Block Extractor
I want block bounding boxes to include the geometry of nested block references
So that trim calculations and content zone detection correctly reflect the actual visual extent of blocks containing nested INSERT references

## Problem Statement

The current `_get_block_bounding_box()` function in `app/core/geometry.py` (lines 262-356) only processes direct entities within a block:
- LINE, LWPOLYLINE, POLYLINE, CIRCLE, ARC, POINT

INSERT entities (block references) are completely ignored. When block A contains an INSERT reference to block B:
- Block A's bounding box only includes block A's direct entities
- Block B's geometry is NOT recursively included
- Result: Undersized bounding boxes and incorrect content zone detection

Example scenario:
- Block `OUTER` has a rectangle from (0,0) to (30,20)
- Block `OUTER` contains INSERT of block `INNER` at position (5,5)
- Block `INNER` has geometry extending to (5,5) in its local coordinate system
- Current behavior: `OUTER` bbox = (0,0,30,20) - ignores INNER
- Expected behavior: `OUTER` bbox should include transformed INNER geometry

## Solution Statement

Implement recursive INSERT geometry expansion with proper coordinate transformation:

1. **Add `_transform_bbox_points()` helper function** that transforms a nested block's bounding box corners by the INSERT entity's properties:
   - Scale (xscale, yscale)
   - Rotation (in radians)
   - Translation (insert point)

2. **Modify `_get_block_bounding_box()` signature** to accept:
   - `doc: Drawing | None = None` - needed for nested block lookup
   - `processed_blocks: set[str] | None = None` - prevents infinite recursion on circular references

3. **Add INSERT entity handling** in the entity loop that:
   - Gets the nested block definition from doc.blocks
   - Recursively calculates the nested block's bounding box
   - Transforms the corners using INSERT properties
   - Adds transformed points to the overall bounding box

4. **Update all call sites** to pass the `doc` parameter where available for nested block expansion.

## Implementation Plan

### Phase 1: Foundation

Add the `_transform_bbox_points()` helper function that implements the coordinate transformation for nested block bounding boxes. This function will be a pure mathematical utility that:
- Takes a bounding box tuple and an INSERT entity
- Extracts INSERT properties: insert point, xscale, yscale, rotation
- Transforms all 4 corners of the bounding box through scale -> rotation -> translation
- Returns list of transformed corner points

Key implementation details:
- Use `insert.dxf.insert` for position (x, y coordinates)
- Use `insert.dxf.xscale` and `insert.dxf.yscale` for scaling (default 1.0)
- Use `insert.dxf.rotation` for rotation angle in degrees (convert to radians)
- Apply transformations in order: scale first, then rotation, then translation

### Phase 2: Core Implementation

Modify `_get_block_bounding_box()` to handle INSERT entities:

1. Update function signature to accept optional `doc` and `processed_blocks` parameters
2. Initialize `processed_blocks` set if not provided
3. Add current block to processed set to prevent revisiting
4. Add INSERT entity handling in the entity loop:
   - Skip if `doc` is None (backward compatibility)
   - Get nested block name from `entity.dxf.name`
   - Check if block exists in `doc.blocks`
   - Check for circular reference in `processed_blocks`
   - Recursively call `_get_block_bounding_box()` for nested block
   - Transform and add nested bbox corners to accumulated points

### Phase 3: Integration

1. Update call site in `extractor.py` to pass `doc` parameter
2. Ensure backward compatibility (function works without `doc` parameter)
3. Update any tests that directly call `_get_block_bounding_box()`
4. Verify no regressions in existing functionality

### Step 3: Add `_transform_bbox_points()` Helper Function

Add the new helper function to `app/core/geometry.py`, inserting it before `_get_block_bounding_box()` (around line 260):

- Function signature: `_transform_bbox_points(bbox: tuple[float, float, float, float], insert: Any) -> list[tuple[float, float]]`
- Extract all 4 corners from bbox: (min_x, min_y), (max_x, min_y), (max_x, max_y), (min_x, max_y)
- Get INSERT properties: `insert.dxf.insert`, `insert.dxf.xscale`, `insert.dxf.yscale`, `insert.dxf.rotation`
- For each corner:
  - Apply scale: `x *= scale_x`, `y *= scale_y`
  - Apply rotation: `x_rot = x * cos(r) - y * sin(r)`, `y_rot = x * sin(r) + y * cos(r)`
  - Apply translation: `x_final = x_rot + insert_x`, `y_final = y_rot + insert_y`
- Return list of 4 transformed points

### Edge Cases

1. **Simple nesting** - Block A contains INSERT of Block B at origin with no transform
2. **Position offset** - INSERT with non-zero position (translation only)
3. **Uniform scale** - INSERT with xscale=yscale (e.g., 2x)
4. **Non-uniform scale** - INSERT with xscale != yscale
5. **Rotation** - INSERT with 90, 45, or arbitrary degree rotation
6. **Combined transforms** - INSERT with scale + rotation + position
7. **Circular reference** - Block A -> Block B -> Block A (should not infinite loop)
8. **Deep nesting** - Block A -> Block B -> Block C (multi-level recursion)
9. **Missing block** - INSERT references block not in doc.blocks
10. **No doc parameter** - Backward compatibility: function called without doc
11. **Empty nested block** - INSERT references block with no geometry

## Notes

1. **Import statement**: The `math` module is already imported in `geometry.py` (line 22), so no additional imports needed for the helper function.

2. **Test import update**: The test file `test_geometry.py` will need to add `_transform_bbox_points` to its imports from `core.geometry`.

3. **INSERT properties defaults**: ezdxf INSERT entities have default values:
   - `xscale`, `yscale`: default 1.0
   - `rotation`: default 0.0 degrees

4. **Transformation order**: The standard order is Scale -> Rotate -> Translate. This matches how CAD systems apply INSERT transformations.

5. **Reference document**: Detailed analysis in `ai_output/087-geometry-handling-gap-analysis-report.md` Section 1.2.

6. **Prior unit learnings**:
   - **Unit 1 (LWPOLYLINE Bulge)**: Used `make_path()` (not `from_vertices()`) for proper path handling. Pattern: Create test asset generator script, generate DXF, then add comprehensive tests. Tests went from 1039 to 1049.
   - **ARC bbox**: Added `_get_arc_bounding_box()` helper function for accurate calculations. Similar pattern of adding helper function applies here.

7. **Performance consideration**: Recursive bbox calculation adds computational cost for deeply nested blocks. The circular reference protection prevents infinite loops. For most CAD drawings, nesting depth is shallow (2-3 levels).

8. **Future enhancement**: The `_detect_content_zone()` function could also benefit from nested INSERT expansion, but that is out of scope for this unit. It would require similar recursive handling for edge extraction.
